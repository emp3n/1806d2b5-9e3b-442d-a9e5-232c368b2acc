# cloudflared — карточка сервиса (дизайн-лаборатория)

Пять разделов на рейле справа — **Overview, Services, Database, Shell, Logs**.
Собран только Services: карточка cloudflared. Остальные четыре — пустые
заглушки (название и слово `empty`), ничего не выдумано.

## Запуск

```sh
cd redesign
./tools/connector.sh start          # настоящий cloudflared (см. REAL-DATA.md)
./tools/serve.sh start              # страница + лента на одном адресе
```

http://localhost:8599 · health: `/_stcore/health` · лента: `/api/state`

`serve.sh` поднимает пару процессов: шлюз на **публичном** порту (8599) и
Streamlit сразу за ним (8600). Туннелю менять ничего не нужно — он продолжает
ходить на `localhost:8599`, просто этот адрес теперь отвечает и на `/api/state`.
`serve.sh status` печатает, что из трёх частей живо; `stop` гасит обе.

Скрипт сам выбирает интерпретатор, в котором есть Streamlit (`PYTHON=…`
переопределяет), и проверяет готовность шлюза по ответу
`{"gateway": true}`, а не по коду 200: Streamlit отвечает 200 со своим HTML на
любой незнакомый путь, так что «кто-то отозвался» — это ещё не шлюз.

Только для себя, без телефона и туннеля, хватает одного процесса:

```sh
streamlit run main.py --server.port 8599
```

Параметры URL: `?theme=light|dark|auto` (по умолчанию `dark`, `auto` — по ОС),
`?section=overview|services|database|shell|logs`, `?incident=0|1`, `?tick=N`,
`?source=live|sample`.

Страница — один полноэкранный холст: `html, body` и `.rd-stage` держат
`100vh` с `overflow: hidden`, содержимое центрируется по обеим осям, полосы
прокрутки нет ни на одном размере окна. Оболочка Streamlit тоже убрана —
шапка, тулбар и отступы скрыты, iframe растянут на `100vw × 100vh`, поэтому
фон занимает всё окно, а не висит карточкой в белом поле. Если окно ниже
карточки, кадр масштабируется (`scale(0.62…1)`, замеры в `REAL-DATA.md`), а не
обрезается: прокрутки по-прежнему нет.

## Деплой (Streamlit Cloud)

Папка `redesign/` — самодостаточный проект: её содержимое пушится в корень
репозитория, entry point — `main.py`, зависимости — `requirements.txt`.
Основная панель репозитория не меняется и в этот пакет не входит.

На `*.streamlit.app` свой шлюз и свой `cloudflared` рядом с приложением
не крутятся, и Streamlit Cloud не проксирует произвольный `/api/state`. Поэтому
`bootstrap.py` в `app.py`:

1. скачивает `cloudflared` в `.temp/` (папка создаётся сама; `CARD_RUNTIME`
   переопределяет путь, бинарник не коммитится — см. `.gitignore`);
2. поднимает quick tunnel без токена до встроенной ленты `127.0.0.1:8598`;
3. читает публичный `https://…trycloudflare.com` из лога и отдаёт его карточке
   явным адресом ленты;
4. при отказе показывает причину и **код выхода**, включая 255, вместо того
   чтобы оставить на экране замороженные числа.

`?source=sample` работает вообще без сети и без бинарника — запасной режим для
первого запуска. `CARD_TUNNEL=off` отключает загрузку туннеля (для локальной
разработки он и так не нужен: там лента живёт на своём origin через
`gateway.py`).

## Живые данные

По умолчанию карточка читает настоящий `cloudflared` на этой машине
(`?source=live`): pid, путь к бинарнику, CPU и RSS из `/proc`, uptime по
`starttime`, версию и число живых соединений из metrics-эндпоинта, локации
краёв и причину отказа — из лога коннектора, адрес выхода — из
`1.1.1.1/cdn-cgi/trace`. Опрашивать процесс из iframe нельзя, поэтому рядом
живёт лента: поток-сэмплер раз в секунду и HTTP на `127.0.0.1:8598/api/state`,
который страница и читает. Подвал в этом режиме подписан `live · pid N`, строка
статуса — `N of 4 connections live`; если соединений ноль, причина отказа
выводится отдельной красной строкой.

Рабочий туннель на этой машине даёт `4 of 4 connections live` и чип
`Edges fra08, ist03, fra03, fra12` — это `location=` из строк
`Registered tunnel connection` его же лога. Данные живые: `pid` в подвале
меняется вместе с процессом, `uptime` тикает, `CPU`/`RAM` читаются из
`/proc/<pid>` каждую секунду.

Всё, что не читается с процесса, карточка не выдумывает: бюджет 256 MB и «одно
ядро» — соглашение панели (у процесса `memory.max = max`), история рестартов и
политика обновлений требуют Cloudflare API и в живом режиме пусты. Поле за
полем, с командами проверки и замерами: **`REAL-DATA.md`**.

`?source=sample` возвращает прежнюю лабораторную серию с браузерным
генератором — так собираются статические снимки для проверок.

## Один адрес для страницы и ленты

**Что было.** Карточке выдавался адрес ленты `http://127.0.0.1:8598/api/state`.
Для браузера на этой машине это лента; для телефона `127.0.0.1` — сам телефон:
запрос отбивается, `catch` молча ставил атрибут на карточку, и на экране
оставались те числа, которые сервер нарисовал при отдаче HTML. Выглядело это
ровно как живые данные: `4 of 4 connections live`, `uptime`, графики — только
замороженные. Отсюда и «на странице показывается, в телефоне не обновляется»:
на машине с лентой адрес работает, на телефоне — нет, а признака отказа не было
ни одного.

**Правило теперь.** Адрес ленты считает `feed_url()` в `server.py`, и он всегда
про браузер, а не про хост:

| Где открыта страница | Что поллит карточка |
|---|---|
| `localhost:8599`, `127.0.0.1:…` | `http://127.0.0.1:8598/api/state` (как раньше) |
| любой другой хост — туннель, `192.168.…`, телефон | `свой-же-origin` + `/api/state` |
| `CARD_API_URL` или `?api=` | ровно этот адрес |

**Почему «свой origin» — рабочее решение.** Туннель несёт один порт, значит
страница и лента должны жить на одном. Это и делает `gateway.py`: читает первую
строку запроса, `/api/*` отдаёт ленте, всё остальное — Streamlit, а дальше
перекачивает байты в обе стороны, поэтому `/_stcore/stream` (websocket) проходит
через него как есть, без разбора. `/api/gateway` отвечает сам шлюз, чтобы
здоровье можно было проверить отдельно от приложения.

```
phone ──https──> tunnel ──> gateway:8599 ──/api/*──> feed:8598
                                        └──всё───> streamlit:8600
```

Есть у шлюза и вторая обязанность, которую видно только из лога туннеля:
`cloudflared` раскрывает `localhost` сначала в `::1` и только потом в
`127.0.0.1`. Шлюз, слушавший `0.0.0.0`, на первую попытку не отвечал вовсе —
в `cf.log` это 52 строки `dial tcp [::1]:8599: connect: connection refused`, а у
человека с телефоном это «то обновляется, то нет». Поэтому шлюз слушает `::`
одним сокетом на оба семейства (`IPV6_V6ONLY=0`), а не только IPv4.

Отсюда ещё два следствия, и оба в пользу такого расклада: страница и лента
оказываются на `https` (смешанного содержимого нет), и CORS больше не нужен —
но он остался, лента по-прежнему отдаёт `*`, если её открыть напрямую.

**Когда ленты нет, карточка это говорит.** Запрос идёт цепочкой (`setTimeout`,
не `setInterval`), поэтому медленный ответ не наслаивается; у запроса дедлайн
4 с; при отказе — бэкофф 1, 2, 4, 8 и дальше раз в 10 с; при возвращении
вкладки (`visibilitychange`), `pageshow` и `online` опрос идёт немедленно, а в
скрытой вкладке цепочка стоит и батарею не жжёт. Отказ виден: строка статуса
становится `feed unreachable`, числа уходят в 45 % прозрачности, а подвал
называет адрес, который не ответил — `no feed · 127.0.0.1:8598`. На телефоне
эта подпись объясняет всё сразу.

## Кнопки и процесс

Страница в iframe не может ни прочитать `/proc`, ни послать сигнал, поэтому оба
действия идут через ту же ленту: `POST http://127.0.0.1:8598/api/action`.

Три ограничения держат это честным:

1. **Только тот pid, который сэмплер уже читает.** Номер процесса из запроса не
   принимается вообще — тело несёт лишь глагол `stop` / `start` / `restart`.
2. **Только запомненная командная строка.** Строка снимается с
   `/proc/<pid>/cmdline` и хранится в
   `~/.local/state/apLLMe/cf-launch.json` (0600, `CARD_LAUNCH_FILE`
   переопределяет путь). `--token <секрет>` при этом переписывается в
   `--token-file` рядом с бинарником, так что перезапуск не возвращает секрет в
   `/proc/<pid>/cmdline`. Файл нужен ещё и потому, что `/proc` забывает
   командную строку вместе с процессом: панель, открытая после остановки,
   иначе не смогла бы ничего поднять.
3. **Ключ, которого нет в ленте.** Роут требует заголовок `X-RD-Action` со
   случайным ключом, который печатается в HTML страницы и никогда не попадает в
   `/api/state`. Лента отдаёт `Access-Control-Allow-Origin: *` (у iframe
   непрозрачный origin), то есть прочитать числа может кто угодно, а нажать
   кнопку — только тот, кто получил страницу.

Ответ приходит JSON-ом (`{"ok":true,"action":"stop","pid":623992}`) и сразу
пере-сэмплируется, чтобы следующий опрос не показывал секунду старых чисел.

Есть и четвёртое ограничение, про сам туннель: если страница пришла по
публичному имени (`streamlit.idealis.cc`), то коннектор, который гасит кнопка, —
это тот самый коннектор, который несёт страницу. Одно нажатие тогда только
предупреждает (`This page comes through this tunnel — again stops it…`), и лишь
второе в течение четырёх секунд останавливает процесс: иначе телефон одним
касанием отрезал бы сам себя, а вернуть коннектор можно было бы только с машины.
С локального адреса и из локальной сети остановка идёт с первого нажатия —
там туннель ни при чём.

Остановленный коннектор остаётся в `/proc` зомби, пока его не заберёт родитель.
Такой `Z` — не работающий сервис: коллектор считает его отсутствием (иначе
карточка навсегда замирала на «0 of 4 connections live» с кнопкой `Stop`), а
супервизор держит `Popen` своего ребёнка и делает `poll()`, чтобы забирать
зомби после каждого рестарта.

## Что на карточке и почему только это

Сверху вниз, как читают прибор:

| Место | Что | Зачем |
|---|---|---|
| шапка | знак Cloudflare (настоящий path из simple-icons на брендовой плашке; сам знак вписан с полями — 76 % плашки, облако целиком видно и не липнет к краям), `cloudflared`, строка `4 of 4 connections live` | кто это и жив ли туннель |
| шапка справа | две круглые кнопки: **питание** (пуск/остановка) и **перезапуск** | единственные действия |
| чипы | `Origin IP` → адрес выхода, `Edges` → локации соединений (`fra08, ist03, …`; в синтетике `sea11, sea06, sea09, pdx04`) | где стоит коннектор |
| плитка CPU | процент, доля ядра, линия за 48 отсчётов | цена процесса |
| справа от CPU | `uptime` и `version` | сколько живёт и какая сборка |
| полоса | путь к бинарю и копирование | чем запущен |
| плитка RAM | значение, доля лимита, та же линия, переключатель MB/GB | вторая цена |

Выключателя темы на карточке нет — тема приходит из URL или из ОС.

## Показатель и цвет

Цифра — своя единица (`%` ядра для CPU, MB для RAM), а цвет — доля бюджета
сервиса: **1 ядро** и **256 MB**. Порогов три, они дают четыре полосы:

| Полоса | CPU | RAM | Цвет |
|---|---|---|---|
| `ok` | < 25 % ядра | < 30 % лимита | зелёный (`--ok`) |
| `warm` | < 50 % | < 55 % | жёлтый (`--warn`) |
| `hot` | < 80 % | < 80 % | оранжевый (`--hot`) |
| `crit` | ≥ 80 % | ≥ 80 % | красный (`--crit`) |

Поэтому «4 %» на одном бюджете и «4 %» на другом читаются по-разному, а не
всегда зелёным. Цвет ставится и цифре, и каждому отрезку линии: линия — это
форма (нормируется по своему окну), цвет — абсолютная тяжесть отсчёта.

Настоящие данные о машине читаются один раз: `os.cpu_count()` и
`/proc/meminfo` → подпись `host 8 cores · 15.3 GB` в подвале.

## Взаимодействие

- **линия CPU и линия RAM** — скраббер: наведение ставит на линию точку (кружок
в цвет полосы, 10 px, с обводкой в цвет карточки) на выбранном отсчёте и
подменяет цифру и цвет под ним; `←` `→` `Home` `End` двигают точку с
клавиатуры, `Esc` и уход курсора возвращают текущее значение. Пока курсор на
линии, точка едет вместе с ней (отсчёт один и тот же), а подпись доли
пересчитывается.
- **MB / GB** — переключатель; выбранная единица держится, пока её не сменят:
  скраббер, уход курсора и тики генератора форматируют в ней же (GB — два
  знака, `0.07 GB`), а не сбрасывают на MB.
- **пуск/остановка** — в живом режиме это настоящий сигнал процессу:
  `POST /api/action {"action":"stop"}` → `SIGTERM`, ожидание 5 с, затем
  `SIGKILL`, если не пошёл. Карточка сразу перестаёт врать: статус
  «stopped by you», плитки в прочерки, «no process», линия ложится в ноль,
  кнопка меняет подпись на `Start service`. Второй клик поднимает коннектор
  заново из запомненной командной строки, и уже через секунду в подвале новый
  `pid`. В `?source=sample` — прежняя местная имитация (`data-run="stop"`).
- **перезапуск** — двухшаговый в любом режиме: первый клик взводит (красная
  заливка, «Click again»), второй выполняет, через 3,2 с взвод снимается сам.
  В живом режиме это `restart`: `SIGTERM`, ожидание, запуск той же строки —
  новый `pid`, `uptime` с нуля, соединения поднимаются заново.
- **копирование пути** — `Copied` в подсказке на 1,4 с.
- **живая серия** — раз в секунду каждый показатель берёт следующий отсчёт
  (медленный вал из двух синусов + мелкая рябь + редкий всплеск), и окно
  сдвигается ровно на один отсчёт. Рисуется это покадрово
  (`requestAnimationFrame`, 60 fps), поэтому линия не дёргается на тике:
  она непрерывно едет влево, её шкала подтягивается к новому минимуму и
  максимуму экспонентой (не прыжком), а цифра догоняет новое значение за
  ~0.3 с — она накапливается, а не перескакивает раз в секунду. Между
  отсчётами линия — квадратичные кривые: каждый отсчёт это изгиб, стыки
  лежат на серединах между отсчётами, поэтому изломов нет; по краям окна
  дорисованы фантомные отсчёты, так что штрих всегда доходит до рамки, без
  щели справа. Генератор молчит, когда карточка остановлена или вкладка
  скрыта, и не мешает скрабберу: пока курсор на линии, он держит выбранный
  отсчёт.
- **рейл** — пять кружков 76 px, подписей в покое нет вовсе; активный кружок
  залит `--text` (белый в тёмной теме, чёрный в светлой). Наведение только на
  сам кружок: он уходит **вправо на 25 px** и одновременно поворачивается на
  25° по часовой, а из-под него выезжает скруглённая плашка с названием
  раздела (48 px высотой, 340 мс, ширина по слову). Кружок именно уезжает с
  плашки, а не стоит на ней: его правый край встаёт к краю кадра — для этого у
  рейла оставлено 24 px справа; перекрытие плашки с диском 19–27 px, подпись
  остаётся в стороне. Курсор можно увести с кружка на плашку — раздел
  остаётся открытым. Соседние кружки не двигаются.
- смена раздела перезапускает `rd-drop` у содержимого.
- всё выключается `prefers-reduced-motion`.

## Телефон

До 760 px карточка перестаёт быть «одним экраном»: на телефоне нет места, а
уменьшать текст нельзя — 0.7 от 13 px это не подпись. Поэтому там другой
режим, и он не пытается быть уменьшенным десктопом.

**Рейл уезжает вниз.** Пять кружков — это навигация, а не украшение, и палец
живёт внизу экрана: рейл становится полосой, прижатой к нижнему краю
(`position: fixed`, `bottom: 0`), с размытием под ней
(`backdrop-filter: blur(16px) saturate(1.2)`) и отступом под домашний индикатор
(`env(safe-area-inset-bottom)`). Кружки держатся неподвижно: нет выезда на
25 px, нет поворота и нет плашки с названием — на тач-экране плашка осталась
бы открытой после тапа и съела бы ровно тот пробел, из-за которого всё
начиналось. Название раздела живёт в `aria-label` кнопки, так что скринридер
его читает. Активный кружок по-прежнему залит. На ширине до 430 px кружки
52 px, полоса 72 px.

**Карточка листается.** `.rd-stage` на телефоне — скролл-контейнер
(`overflow-y: auto`), карточка в нём одна, отступ снизу равен высоте полосы
(`--dock`), поэтому подвал карточки можно вытащить из-под рейла. Скролла нет,
когда всё влезает: `auto`, а не `scroll`. Полоса прокрутки — своя, из токенов
карточки (10 px, скругление 8 px, `--text` 22 % → 40 % на наведении,
`scrollbar-width: thin` для Firefox), а не серая полоса браузера.

**Никакого масштабирования.** `fit()` на телефоне выходит сразу: масштаб — это
лекарство для короткого окна на десктопе, а не для телефона.

**И это же лечит десктоп.** Если окно настолько низкое, что даже 0.62 не
влезает, карточка больше не обрезается сверху и снизу: `fit()` ставит
`.rd-scroll`, и окно листается — на всю высоту, с обоими концами. Причина, по
которой «до конца не листалось», была в вёрстке: у `.rd-stage` не было
`box-sizing: border-box`, и `padding: 24px 16px` прибавлялся к `100vh` — 48 px
контента оказывались ниже окна и недостижимы при `overflow: hidden`.

**Скраббер на пальце.** У пальца нет наведения: `pointerdown` показывает
отсчёт под ним, `pointerup` отпускает, `pointercancel` (начался скролл)
снимает. По вертикали жест остаётся прокрутке — `touch-action: pan-y` у
графика, поэтому карточку можно листать, начиная жест прямо на линии.

## Ограничения

Кнопки управляют только тем коннектором, который читает сэмплер этого
процесса, и только запомненной командной строкой: чужой `cloudflared`, systemd
или контейнер они не тронут (для них нужен `systemctl`, а это уже не карточка).
Остановка коннектора рвёт живой туннель — на этой машине он поднят из
`tools/connector.sh`, и та же кнопка возвращает его обратно.
Генератор (`?source=sample`) живёт в браузере (1 Гц);
живой режим генератор выключает и берёт отсчёты у процесса. `?incident=1` —
спроектированное состояние синтетики, а не снимок с прода.
Разделы, кроме Services, пустые намеренно.

Адрес ленты считается по адресу страницы, а не по адресу хоста, поэтому
открыть кабинет из другого места можно только через шлюз (`gateway.py`) или
явным `CARD_API_URL`: голая `streamlit … --server.port 8599`, проброшенная
туннелем напрямую, отдаст страницу, но `/api/state` на ней будет 404 от самого
Streamlit. Карточка в этом случае честно скажет `feed unreachable` и назовёт
адрес — молчаливо замороженных чисел больше не бывает.

## Тесты

```sh
python3 -m pytest tests -q                       # 145: 133 unit + 12 с бинарником
python3 -m pytest tests/test_live_binary.py -v    # 12: настоящий бинарник
```

Юниты проверяют разбор `/proc`, метрики, `/ready` (тело 503), лог (JSON и
текст, схлопывание слотов `connIndex`, отсечение прошлой сессии), адрес лога
(`--logfile`, `fd/1`, не пайп), схему состояния против `card.py` и то, что токен
не попадает ни в состояние, ни в пейлоад, ни в HTML. Управление проверяется
отдельно (`tests/test_control.py`, 20 тестов): `SIGTERM` уходит ровно тому pid,
который читает сэмплер; перезапуск даёт новый pid и оставляет один процесс;
ключ обязателен и чужой не принимается; секрет переезжает в файл `0600`, а не
в запомненную строку; зомби читается как «процесса нет», а запущенный ребёнок
забирается, а не висит в `/proc`. Интеграционные запускают
`cloudflared` с `--token-file`, ждут `/metrics` и проверяют, что каждое число
карточки снимается с процесса; без бинарника или файла токена они пропускаются
(`CLOUDFLARED_BIN`, `CLOUDFLARED_TOKEN_FILE`).

Адрес и шлюз — `tests/test_gateway.py` (25): матрица `feed_url` (loopback,
туннель, явный адрес, мусор), маршрутизация `/api/*` против всего остального,
тело и `X-RD-Action` у POST, websocket-байты, 502 с названным портом, две
заявки в одном соединении, `/api/gateway` мимо апстримов. Клиент — в
`tests/test_card_js.py`: отказ называется, а не замораживается; цепочка с
дедлайном и бэкоффом; возобновление по `visibilitychange` / `pageshow` /
`online`; притушенные числа; `data-feed` только у живой карточки; плюс
`serve.sh` — шлюз на публичном порту, Streamlit за ним, `sh -n` чистый.
