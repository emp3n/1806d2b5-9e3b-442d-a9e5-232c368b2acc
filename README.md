# cloudflared — карточка сервиса (дизайн-лаборатория)

Пять разделов на рейле справа — **Overview, Services, Database, Shell, Logs**.
Собран только Services: карточка cloudflared. Остальные четыре — пустые
заглушки (название и слово `empty`), ничего не выдумано.

## Запуск

```sh
cd redesign
./tools/serve.sh start     # страница на порту туннеля + коннектор, оба проверены
./tools/serve.sh status    # что действительно живо, а не что мы думаем
./tools/serve.sh stop
```

`8501` — не предпочтение, а условие: маршрут в Cloudflare уже стоит как
`streamlit.idealis.cc -> http://localhost:8501`, править его из кода нельзя.
Поэтому на порту живёт **сам Streamlit** (страница и числа — один origin), а
`tools/serve.sh` только поднимает его и проверяет `/_stcore/health`.

Туннелем отдельно управляет `tools/connector.sh start|stop|restart|status`;
оба скрипта — тонкие обёртки над `tools/appctl.py`, а тот вызывает ровно те
функции `bootstrap.py`, которые вызывает развёрнутое приложение. Одна
реализация, поэтому CLI и приложение не могут разойтись в том, что такое
«запущено».

Токен ищется в трёх местах, в этом порядке: `CLOUDFLARE_TUNNEL_TOKEN` в
Streamlit secrets → та же переменная в окружении → `.temp/cf-token` (0600).
Токен всегда передаётся файлом (`--token-file`), в `--token` и в argv он не
попадает никогда. Если токена нет вовсе, поднимается **quick tunnel**, так что
`start` не может упасть только из-за отсутствия секрета, — а когда секрет
появится, quick-туннель будет заменён именным (см. «Деплой»).

Порт метрик 20241 — предпочтение, а не требование: если его держит коннектор от
прошлого запуска, берётся свободный, иначе cloudflared выходит сразу с
`bind: address already in use`.

Параметры URL: `?theme=light|dark|auto` (по умолчанию `dark`, `auto` — по ОС),
`?section=overview|services|database|shell|logs`, `?incident=0|1`, `?tick=N`,
`?source=live|sample`. `CARD_TUNNEL=off` отключает туннель целиком (локальная
разработка), `CARD_PORT` переопределяет порт.

Страница — один полноэкранный холст: `html, body` и `.rd-stage` держат
`100vh` с `overflow: hidden`, содержимое центрируется по обеим осям, полосы
прокрутки нет ни на одном размере окна. Оболочка Streamlit тоже убрана —
шапка, тулбар и отступы скрыты, iframe растянут на `100vw × 100vh`, поэтому
фон занимает всё окно, а не висит карточкой в белом поле. Если окно ниже
карточки, кадр масштабируется (`scale(0.62…1)`, замеры в `REAL-DATA.md`), а не
обрезается: прокрутки по-прежнему нет.

## Деплой (Streamlit Cloud)

Папка `redesign/` — самодостаточный проект: её содержимое пушится в корень
репозитория, entry point — `main.py`, зависимости — `requirements.txt`.
Основная панель репозитория не меняется и в этот пакет не входит.

На Cloud коннектор поднимает само приложение, и токен приходит **секретом**:

| Секрет | Зачем |
|---|---|
| `CLOUDFLARE_TUNNEL_TOKEN` | токен именного туннеля; без него будет quick-туннель |
| `CLOUDFLARE_TUNNEL_HOSTNAME` | публичное имя для карточки (по умолчанию `streamlit.idealis.cc`) |
| `CARD_CLOUD_URL` | адрес самого деплоя (`https://<subdomain>.streamlit.app`) — тот, что переживает остановку туннеля |
| `CARD_EXEC_TOKEN` | ключ для `cloud_exec` (удалённое исполнение в контейнере) |

Что делает `bootstrap.py` в `app.py`, по шагам:

1. **перенимает** уже работающий коннектор (pidfile → `/proc` → `--metrics` →
   `/ready` ≥ 1), потому что скрипт на Cloud перезапускается куда чаще
   контейнера, и только если такого нет —
2. **скачивает** `cloudflared` в `.temp/` (папка создаётся сама; `CARD_RUNTIME`
   переопределяет путь, бинарник не коммитится — см. `.gitignore`) и
   **запускает именной туннель** с токеном из секрета: `tunnel --metrics … run
   --token-file .temp/cf-token`, файл 0600, в argv секрета нет;
3. если токена нет — поднимает quick tunnel и берёт публичный адрес из лога;
   **как только токен появился, quick заменяется именным** (сначала новый
   коннектор регистрируется, потом гасится старый) — иначе приложение навсегда
   оставалось на `*.trycloudflare.com`, а имя оператора отвечало 530;
4. при отказе показывает причину и **код выхода**, включая 255, вместо того
   чтобы оставить на экране замороженные числа.

`static/` отдаёт сам Streamlit: в `.streamlit/config.toml` включён
`server.enableStaticServing`. Карточка запрашивает **относительный** путь
`bootstrap.CARD_STATE_PATH = "app/static/state.json"` — браузер разрешает его
против документа приложения: `/` на обычном хосте и `/~/+/` в Community Cloud.
С ведущим `/` на Cloud запрос уходил мимо префикса вьюера, попадал в цикл
редиректов и отдавал HTML-оболочку — это и было «state unreachable» при живых
данных через туннель. Ни прокси, ни второго порта.

### Что в Streamlit можно, а что нельзя (и через что прокидывать)

Здесь собраны именно те факты, которых не хватало, пока разбирались с
«нереагирующими» кнопками и ошибками в логах. Все проверены на 1.64.0.

| Хочу | Как | Почему не иначе |
|---|---|---|
| Отдать данные браузеру без второго сервера | `server.enableStaticServing = true`, файл в `static/`, путь считается из `st.context.url`: `/app/static/<file>` либо `/~/+/app/static/<file>` | Другого origin нет; но на Community Cloud есть префикс вьюера, и жёсткий leading-slash путь отдаёт HTML вместо JSON |
| Перезаписывать такой файл раз в секунду | `write_state()` дописывает пробелы до **16384 байт**, пишет в уникальный `mkstemp`-файл и делает `os.replace` | Starlette'овский `stream_file()` берёт `Content-Length` из `stat()` **до** чтения; файл меняющейся длины даёт `Response content shorter/longer than Content-Length` (было 176 сбоев на 1200 GET). Общий `state.json.new` при двух writer'ах во время ребута давал `FileNotFoundError` в `os.replace` — теперь temp-файл уникален на каждую запись |
| Нажимать кнопку внутри iframe и менять состояние процесса | Кнопка уходит на `?rd=stop\|start\|restart`; `app.py` читает параметр **до** отрисовки, выполняет действие, чистит параметр | `st.iframe` ставит sandbox без `allow-top-navigation`, поэтому `window.top.location` из него недоступен; app пишет свой `<iframe>` с этим разрешением |
| Передать действие в приложение | Один канал `?rd=`, единственный владелец глагола — `statefeed.Sampler.act()` | Второй HTTP-эндпоинт создаёт второго владельца коннектора; раньше именно так кнопки и пропали с карточки |
| Заставить rerun после смены URL | Полная навигация (`location.replace`) | `st.query_params` меняет URL через `history.pushState`, но **сам не вызывает rerun** |
| Выполнить код внутри контейнера | `mcp_exec.py` + `CARD_EXEC_TOKEN`, `?exec=` | HTTP-роуты Streamlit read-only; `st.html` исполняет JS только в браузере, до Python он не добирается |

`?source=sample` работает вообще без сети и без бинарника — запасной режим для
первого запуска.

## Живые данные

По умолчанию карточка читает настоящий `cloudflared` на этой машине
(`?source=live`): pid, путь к бинарнику, CPU и RSS из `/proc`, uptime по
`starttime`, версию и число живых соединений из metrics-эндпоинта, локации
краёв и причину отказа — из лога коннектора, адрес выхода — из
`1.1.1.1/cdn-cgi/trace`.

Опрашивать процесс из iframe нельзя, поэтому рядом живёт `statefeed.Sampler`:
поток раз в секунду снимает показания и **атомарно** (`os.replace`)
переписывает `static/state.json`, который страница и читает. В пейлоаде есть
`ts` — отметка записи, она и есть сердцебиение: пока файл переписывается,
числа живые; если отметка перестала меняться дольше 12 секунд, карточка
переходит в `stalled` и гасит числа, а не выдаёт последние приятные за
настоящие. Сравнение идёт с **собственным** предыдущим наблюдением, а не с
`Date.now()` против серверного `ts`: часы телефона могут убежать на минуты, и
такое сравнение объявляло живую ленту мёртвой.

Подвал в этом режиме подписан `live · pid N`, строка статуса — `N of 4
connections live`; если соединений ноль, причина отказа выводится отдельной
красной строкой. `Edges` перечисляет каждый край один раз: четыре соединения
обычно ложатся на два края, и `sea01, sea07, sea07, sea01` читалось как ошибка
в числах.

Всё, что не читается с процесса, карточка не выдумывает: бюджет памяти и «одно
ядро» — соглашение панели (у процесса `memory.max = max`), история рестартов и
политика обновлений требуют Cloudflare API и в живом режиме пусты. Поле за
полем, с командами проверки и замерами: **`REAL-DATA.md`**.

`?source=sample` возвращает прежнюю лабораторную серию с браузерным
генератором — так собираются статические снимки для проверок.

## Один адрес для страницы и чисел

**Что было.** Карточке выдавался адрес ленты `http://127.0.0.1:8598/api/state`,
а кнопки ходили на третий порт через самодельный шлюз (`gateway.py`). Туннель
несёт **один** порт, поэтому шлюз приходилось ставить перед Streamlit, а ленту
прятать за ним: два лишних процесса, websocket сквозь самодельный прокси,
отдельный ключ `X-RD-Action` и целый класс отказов, которые к туннелю
отношения не имеют. На Cloud это не работало вовсе: там слушает только
Streamlit на 8501, и `/api/state` на нём — 404.

**Правило теперь.** Один порт, один канал, один владелец коннектора. Числа
лежат в файле, который отдаёт сам Streamlit, и карточка читает его **со своего
же origin**:

| Где открыта страница | Что поллит карточка |
|---|---|
| `localhost:8501` | `/app/static/state.json` |
| `streamlit.idealis.cc` | `/app/static/state.json` (тот же файл через туннель) |
| `*.streamlit.app` | `/~/+/app/static/state.json` (префикс вьюера Cloud) |

Путь относительный, без ведущего `/`: srcdoc-iframe разрешает его против
документа приложения (`/` или `/~/+/`). Ни `CARD_API_URL`, ни CORS, ни догадок
о «своём» адресе не осталось. Кнопки не навигируют ни `top`, ни `parent`:
сам вьюер Cloud — песочница, и браузер запрещает потомку навигировать любого
предка (консоль: *disallowed from navigating its ancestors*). Карточка шлёт
`postMessage` с одним из трёх глаголов, а документ приложения ловит его через
`st.html(unsafe_allow_javascript=True)` и перезагружает **себя** с `?rd=`.

Заодно убрана обратная связь, из-за которой туннель перезапускался сам:
проверка публичного имени из контейнера Cloud получает **403** от edge даже при
четырёх живых соединениях, и старая схема struck-счётчиков объявляла коннектор
«застрявшим». Живость теперь определяется только по `/proc` и `/ready` ≥ 1;
`public_answers()` остался диагностической функцией и больше не убивает
коннектор.

**Когда чисел нет, карточка это говорит.** Запрос идёт цепочкой
(`setTimeout`, не `setInterval`), поэтому медленный ответ не наслаивается; у
запроса дедлайн 4 с; при отказе — бэкофф 1, 2, 4, 8 и дальше раз в 10 с; при
возвращении вкладки (`visibilitychange`), `pageshow` и `online` опрос идёт
немедленно, а в скрытой вкладке цепочка стоит и батарею не жжёт. Каждый запрос
несёт `?t=Date.now()`: у статики нет `Cache-Control`, и эвристический кеш
браузера иначе заморозил бы карточку на минуты.

Отказ виден: строка статуса становится `state unreachable`, числа уходят в
45 % прозрачности, а подвал называет путь, который не ответил —
`no state · /app/static/state.json`. Это файл, который публикует сам сервер
страницы, поэтому отказ означает, что приложение под ней ушло, а не что
«какой-то другой хост отказал».

## Кнопки и процесс

Круглые Stop и Restart живут **в шапке карточки**. Iframe не может ни прочитать
`/proc`, ни послать сигнал, поэтому клик уходит `postMessage` в документ
приложения; там он нажимает одну из трёх невидимых нативных кнопок Streamlit.
Нативный клик — это rerun по уже открытому WebSocket: страница **не**
перезагружается и не рендерится заново, глагол исполняется в том же процессе,
что и сэмплер (`statefeed.Sampler.act()` → `bootstrap`), а результат приходит
обратно в `state.json` и показывается **внизу карточки** её собственным
уведомлением. Никакого тоста в правом верхнем углу и никакой замены страницы.

Четыре правила держат это честным:

1. **«Запущено» — это `/ready`.** Не живой pid, не pidfile, не строка в логе:
   пока `/ready` не вернул `readyConnections ≥ 1`, коннектор не считается
   работающим, и карточка говорит `N of 4 connections live`, а не «всё хорошо».
2. **Зомби — это не процесс.** Остановленный коннектор остаётся в `/proc`
   состоянием `Z`, пока родитель его не заберёт; такой pid читается как
   отсутствие (иначе карточка навсегда замирала на «0 of 4» с кнопкой `Stop`).
3. **Перезапуск — это swap, а не убийство.** Сначала стартует новый коннектор и
   ждёт регистрации, только потом гасится старый. Неудачный старт оставляет
   работающий коннектор живым, а не тёмный сайт: на одном туннеле не может быть
   двух коннекторов, но и нуля быть не должно.
4. **Остановка запоминается.** Каждое взаимодействие со Streamlit перезапускает
   скрипт, а `ensure_tunnel` вызывается на каждом прогоне — без записанного
   намерения коннектор возвращался через секунду после Stop. Намерение лежит в
   `.temp/tunnel.intent` (`on`/`off`) и переживает rerun, перезагрузку страницы
   и перезапуск скрипта; сбрасывается оно вместе с контейнером, поэтому
   передеплой поднимает туннель, а не оставляет сайт тёмным.

Если страница пришла по имени туннеля, то кнопка `⏻` гасит **тот самый**
коннектор, который несёт страницу: одно нажатие только взводит подтверждение
(`⏻` + `✕`) и говорит, какое имя закроется и куда возвращаться, второе —
останавливает. Взвод истекает через 45 секунд: подтверждение, забытое на
экране телефона, не должно превратить следующее касание в остановку. Адрес
возврата берётся из `CARD_CLOUD_URL`, потому что имя туннеля после остановки
отвечает 530 и вернуться по нему нельзя.

## Скорость и ресурсы

- `/ready` опрашивается каждые **0.05 с** (было 0.3 с): регистрация нового
  коннектора замечается сразу, а не на следующей итерации.
- `stop_tunnel()` даёт SIGTERM **1 с** (было 5 с) и ждёт SIGKILL **0.5 с**
  (было 3 с). В логах теперь есть `stopped [...] in X.XXs`,
  `registered in X.XXs` и `restart finished in X.XXs` — длительность видна,
  а не предполагается.
- Ядра и память берутся из cgroups: `resources.available_cores()` читает
  `cpu.max` (quota/period), затем `cpuset.cpus.effective` и affinity;
  `resources.memory_limit_bytes()` читает `memory.max`. На Cloud это **16
  CPU / 3 GiB**, тогда как `/proc/meminfo` и `os.cpu_count()` описывают хост
  (125 GB). Ничего не захардкожено.
- CPU карточки — это процент **всего доступного пула**: однопоточные 6 % при
  16 ядрах показываются как 0.38 % of 16 cores, а не «6 % от ядра».
- Версия live-процесса берётся из метрик cloudflared, а при их отсутствии —
  из самого бинарника (`bootstrap.version_of`), закешированного по пути.
  Хардкод `VERSION` остался только в синтетическом демо-режиме.

## Что на карточке и почему только это

Сверху вниз, как читают прибор:

| Место | Что | Зачем |
|---|---|---|
| шапка | знак Cloudflare (настоящий path из simple-icons на брендовой плашке; сам знак вписан с полями — 76 % плашки, облако целиком видно и не липнет к краям), `cloudflared`, строка `4 of 4 connections live` | кто это и жив ли туннель |
| шапка справа | две круглые кнопки: **питание** (пуск/остановка) и **перезапуск** | единственные действия |
| чипы | `Origin IP` → адрес выхода, `Edges` → локации соединений (`fra08, ist03, …`; в синтетике `sea11, sea06, sea09, pdx04`) | где стоит коннектор |
| плитка CPU | процент, доля ядра, линия за 48 отсчётов | цена процесса |
| справа от CPU | `uptime` и `version` | сколько живёт и какая сборка |
| полоса | путь к бинарю и копирование | чем запущен |
| плитка RAM | значение, доля лимита, та же линия, переключатель MB/GB | вторая цена |

Выключателя темы на карточке нет — тема приходит из URL или из ОС.

## Показатель и цвет

Цифра — своя единица (`%` ядра для CPU, MB для RAM), а цвет — доля бюджета
сервиса: **1 ядро** и **256 MB**. Порогов три, они дают четыре полосы:

| Полоса | CPU | RAM | Цвет |
|---|---|---|---|
| `ok` | < 25 % ядра | < 30 % лимита | зелёный (`--ok`) |
| `warm` | < 50 % | < 55 % | жёлтый (`--warn`) |
| `hot` | < 80 % | < 80 % | оранжевый (`--hot`) |
| `crit` | ≥ 80 % | ≥ 80 % | красный (`--crit`) |

Поэтому «4 %» на одном бюджете и «4 %» на другом читаются по-разному, а не
всегда зелёным. Цвет ставится и цифре, и каждому отрезку линии: линия — это
форма (нормируется по своему окну), цвет — абсолютная тяжесть отсчёта.

Настоящие данные о машине читаются один раз: `os.cpu_count()` и
`/proc/meminfo` → подпись `host 8 cores · 15.3 GB` в подвале.

## Взаимодействие

- **линия CPU и линия RAM** — скраббер: наведение ставит на линию точку (кружок
в цвет полосы, 10 px, с обводкой в цвет карточки) на выбранном отсчёте и
подменяет цифру и цвет под ним; `←` `→` `Home` `End` двигают точку с
клавиатуры, `Esc` и уход курсора возвращают текущее значение. Пока курсор на
линии, точка едет вместе с ней (отсчёт один и тот же), а подпись доли
пересчитывается.
- **MB / GB** — переключатель; выбранная единица держится, пока её не сменят:
  скраббер, уход курсора и тики генератора форматируют в ней же (GB — два
  знака, `0.07 GB`), а не сбрасывают на MB.
- **пуск/остановка** — в живом режиме это настоящий сигнал процессу:
  `POST /api/action {"action":"stop"}` → `SIGTERM`, ожидание 5 с, затем
  `SIGKILL`, если не пошёл. Карточка сразу перестаёт врать: статус
  «stopped by you», плитки в прочерки, «no process», линия ложится в ноль,
  кнопка меняет подпись на `Start service`. Второй клик поднимает коннектор
  заново из запомненной командной строки, и уже через секунду в подвале новый
  `pid`. В `?source=sample` — прежняя местная имитация (`data-run="stop"`).
- **перезапуск** — двухшаговый в любом режиме: первый клик взводит (красная
  заливка, «Click again»), второй выполняет, через 3,2 с взвод снимается сам.
  В живом режиме это `restart`: `SIGTERM`, ожидание, запуск той же строки —
  новый `pid`, `uptime` с нуля, соединения поднимаются заново.
- **копирование пути** — `Copied` в подсказке на 1,4 с.
- **живая серия** — раз в секунду каждый показатель берёт следующий отсчёт
  (медленный вал из двух синусов + мелкая рябь + редкий всплеск), и окно
  сдвигается ровно на один отсчёт. Рисуется это покадрово
  (`requestAnimationFrame`, 60 fps), поэтому линия не дёргается на тике:
  она непрерывно едет влево, её шкала подтягивается к новому минимуму и
  максимуму экспонентой (не прыжком), а цифра догоняет новое значение за
  ~0.3 с — она накапливается, а не перескакивает раз в секунду. Между
  отсчётами линия — квадратичные кривые: каждый отсчёт это изгиб, стыки
  лежат на серединах между отсчётами, поэтому изломов нет; по краям окна
  дорисованы фантомные отсчёты, так что штрих всегда доходит до рамки, без
  щели справа. Генератор молчит, когда карточка остановлена или вкладка
  скрыта, и не мешает скрабберу: пока курсор на линии, он держит выбранный
  отсчёт.
- **рейл** — пять кружков 76 px, подписей в покое нет вовсе; активный кружок
  залит `--text` (белый в тёмной теме, чёрный в светлой). Наведение только на
  сам кружок: он уходит **вправо на 25 px** и одновременно поворачивается на
  25° по часовой, а из-под него выезжает скруглённая плашка с названием
  раздела (48 px высотой, 340 мс, ширина по слову). Кружок именно уезжает с
  плашки, а не стоит на ней: его правый край встаёт к краю кадра — для этого у
  рейла оставлено 24 px справа; перекрытие плашки с диском 19–27 px, подпись
  остаётся в стороне. Курсор можно увести с кружка на плашку — раздел
  остаётся открытым. Соседние кружки не двигаются.
- смена раздела перезапускает `rd-drop` у содержимого.
- всё выключается `prefers-reduced-motion`.

## Телефон

До 760 px карточка перестаёт быть «одним экраном»: на телефоне нет места, а
уменьшать текст нельзя — 0.7 от 13 px это не подпись. Поэтому там другой
режим, и он не пытается быть уменьшенным десктопом.

**Рейл уезжает вниз.** Пять кружков — это навигация, а не украшение, и палец
живёт внизу экрана: рейл становится полосой, прижатой к нижнему краю
(`position: fixed`, `bottom: 0`), с размытием под ней
(`backdrop-filter: blur(16px) saturate(1.2)`) и отступом под домашний индикатор
(`env(safe-area-inset-bottom)`). Кружки держатся неподвижно: нет выезда на
25 px, нет поворота и нет плашки с названием — на тач-экране плашка осталась
бы открытой после тапа и съела бы ровно тот пробел, из-за которого всё
начиналось. Название раздела живёт в `aria-label` кнопки, так что скринридер
его читает. Активный кружок по-прежнему залит. На ширине до 430 px кружки
52 px, полоса 72 px.

**Карточка листается.** `.rd-stage` на телефоне — скролл-контейнер
(`overflow-y: auto`), карточка в нём одна, отступ снизу равен высоте полосы
(`--dock`), поэтому подвал карточки можно вытащить из-под рейла. Скролла нет,
когда всё влезает: `auto`, а не `scroll`. Полоса прокрутки — своя, из токенов
карточки (10 px, скругление 8 px, `--text` 22 % → 40 % на наведении,
`scrollbar-width: thin` для Firefox), а не серая полоса браузера.

**Никакого масштабирования.** `fit()` на телефоне выходит сразу: масштаб — это
лекарство для короткого окна на десктопе, а не для телефона.

**И это же лечит десктоп.** Если окно настолько низкое, что даже 0.62 не
влезает, карточка больше не обрезается сверху и снизу: `fit()` ставит
`.rd-scroll`, и окно листается — на всю высоту, с обоими концами. Причина, по
которой «до конца не листалось», была в вёрстке: у `.rd-stage` не было
`box-sizing: border-box`, и `padding: 24px 16px` прибавлялся к `100vh` — 48 px
контента оказывались ниже окна и недостижимы при `overflow: hidden`.

**Скраббер на пальце.** У пальца нет наведения: `pointerdown` показывает
отсчёт под ним, `pointerup` отпускает, `pointercancel` (начался скролл)
снимает. По вертикали жест остаётся прокрутке — `touch-action: pan-y` у
графика, поэтому карточку можно листать, начиная жест прямо на линии.

## Ограничения

Кнопки управляют только тем коннектором, который находит `bootstrap` через
pidfile → `/proc` → `/ready`: чужой `cloudflared`, systemd или контейнер они не
тронут (для них нужен `systemctl`, а это уже не карточка).

Остановка коннектора рвёт живой туннель, и если страница открыта по имени
туннеля, она закрывается вместе с ним. Возврат — по адресу деплоя
(`CARD_CLOUD_URL`, то есть `https://<subdomain>.streamlit.app`): там кнопка `▶`
поднимает коннектор заново. Это не недосмотр, а следствие того, что страница и
туннель — один канал.

На одном туннеле не должно быть двух коннекторов: край балансирует трафик между
ними, и один из них может указывать на устаревшую копию приложения. Поэтому
локальный `connector.sh start` при живом коннекторе на Cloud — это разделённый
трафик, а не «второй экземпляр для проверки»; интеграционные тесты по этой же
причине выключены по умолчанию.

Генератор (`?source=sample`) живёт в браузере (1 Гц); живой режим генератор
выключает и берёт отсчёты у процесса. `?incident=1` — спроектированное
состояние синтетики, а не снимок с прода. Разделы, кроме Services, пустые
намеренно.
