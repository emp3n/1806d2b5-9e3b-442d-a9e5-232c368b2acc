# Аудит тайм-аутов

Каждый сетевой вызов и каждый цикл ожидания имеет явный предел. Ниже — полный
список с обоснованием. Значения проверяются тестом `tests/test_timeouts.py`.

## Сеть (server-side)

| Где | Тайм-аут | Почему именно столько |
|---|---|---|
| `core/live.py:HTTP_TIMEOUT` | **0.8 с** | `/ready` и `/metrics` — localhost, отвечают за миллисекунды. 0.8 с оставляет запас для загруженного контейнера и не даёт сэмплеру зависнуть на мёртвом эндпоинте. При 0.5-секундном интервале 0.8 с — максимум, чтобы цикл не накладывался сам на себя. |
| `core/geo.py:TIMEOUT` | **1.5 с** | ipwho.is через HTTPS. Гео резолвится один раз на IP и кешируется, так что медленный ответ возможен только при первом появлении адреса. |
| `core/bootstrap/config.py:VERSIONS_TIMEOUT` | **2.0 с** | GitHub tags API для списка релизов; один вызов на процесс, кешируется, при отказе — статический список. |
| `core/geo.py:TIMEOUT` (disambiguate) | тот же **1.5 с** | тот же публичный HTTPS-источник, один вызов на процесс. |
| `core/bootstrap.py:metrics_answers` | **1.5 с**, аргумент | локальная проба при повторном использовании чужого туннеля. |
| `core/bootstrap.py:ready_connections` | **1.5 с**, аргумент | readiness перед тем, как считать туннель живым. |
| `core/bootstrap.py:public_answers` | **5.0 с**, аргумент | end-to-end через Cloudflare и туннель: сюда входит DNS, edge и сеть. |
| `core/bootstrap.py:state_answers` | **5.0 с**, аргумент | тот же публичный маршрут, но проверяет JSON, а не health. |
| `core/bootstrap.py:download_url` | **25 с** | загрузка бинарника cloudflared (~40 МБ); после неё проверяется минимальный размер. |
| `core/bootstrap.py:version_of` | **15 с** | `cloudflared --version` — subprocess, который может зависнуть на повреждённом бинарнике. |

Все сетевые пробы ловят исключение и возвращают «нет ответа» (False/0), а не
поднимают ошибку: недоступный туннель — нормальное состояние карточки.

## Циклы и ожидание

| Где | Значение | Назначение |
|---|---|---|
| `core/statefeed.py:INTERVAL` | **0.5 с** | период записи `state.json`; атомарная замена фиксированной длины. |
| `core/statefeed.py:_loop` | `_stop.wait(interval)` |прерывимое ожидание, стоп мгновенный. |
| `core/live.py:Collector._loop` | `time.sleep(1.0)` | внутренний такт сэмплера. |
| `core/bootstrap.py:692` | `sleep(0.4)` | ожидание готовности дочернего процесса после запуска. |
| `core/bootstrap.py:592,879,893` | `sleep(0.02–0.05)` | короткие опросы pid/порта, не блокируют UI. |

## Браузер (client-side)

| Где | Значение | Назначение |
|---|---|---|
| `ui/card.js:BEAT` | **500 мс** | интервал опроса `state.json` (вдвое чаще изначальной секунды). |
| `ui/card.js:PATIENCE` | **4000 мс** | AbortController обрывает зависший fetch. |
| `ui/card.js:CEILING` | **10000 мс** | верхняя граница экспоненциальной backoff-задержки при пропаже фида. |
| `ui/card.js:FLOOR` | **0.62** | минимальный масштаб, ниже которого окно скроллится, а не сжимается. |
| `ui/card.js:RD_STALE` | **12 с** | возраст heartbeat, после которого цифры помечаются как устаревшие. |
| `ui/card.js:fit()` | `setTimeout(fit, 600)` | пересчёт масштаба после загрузки шрифтов. |

Backoff: `BEAT * 2^(misses-1)`, ограниченный `CEILING`. Скрытая вкладка не
опрашивает фид вовсе; возврат (`visibilitychange`, `pageshow`, `online`)
сбрасывает счётчик ошибок и опрашивает немедленно.

## Почему именно так

- **Локальные пробы быстрые (0.8–1.5 с), публичные — медленные (5 с).** Разница
  между localhost и Cloudflare на порядок, и одинаковый тайм-аут либо душил бы
  публичную проверку, либо подвешивал локальную.
- **Опрос карты 500 мс + тайм-аут 4 с** означают, что зависший запрос не может
  заблокировать следующий: запросы идут цепочкой, а не параллельно.
- **Гео кешируется**, поэтому 1.5 с платится один раз на IP, а не на каждый тик.
- **Stale = 12 с** при интервале записи 0.5 с: 24 пропущенных тика подряд —
  уже точно сломанный сэмплер, а не сетевой джиттер.

## Исправленные задержки

- **Тики сэмплера** (`Sampler._loop`): раньше `wait(INTERVAL)` считался после
  самплирования (0.5–1.5 с), из-за чего период плавал. Теперь номер тика
  считается от `time.monotonic()`, а ожидание — просто `next_tick - now`.
  Замер: 0.495–0.502 с между записями `state.json` вместо 0.5–1.5 с.
- **Клик Star/Restart**: `ensure_tunnel`/`restart_tunnel` ждут регистрации
  коннектора до 30 с. Это ушло в daemon-поток `_launch()`, а ответ о нажатии
  пишется в `state.json` без повторного опроса. Повторное обновление
  фида публикует итог уже фоновым потоком — страница не залипает.

- **Закачка:** общий тайм-аут 25 с на HTTP-ответ, плюс чтение 40 МБ для проверки
  совместимости (сканирование `--token-file` без запуска процесса). Прогресс обновляется на каждом чанке
  64 КБ, поэтому полоска показывает реальные байты, а не оценку времени.
